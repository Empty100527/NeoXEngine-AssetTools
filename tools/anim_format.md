## 1. 文件整体布局（version 532）

```
偏移        内容
[0x000:0x020]  动作名，32 字节，\0 填充（如 "shoot_jump_01_u_01"）
[0x020:0x040]  根骨骼名，32 字节（如 "biped root"）
[0x040:0x042]  u16 骨骼数 N（51 或 52）
[0x042: ...  ]  N × 32 字节骨骼名表（顺序 = 骨架骨骼顺序）
数据头 16 字节:
    u32  fps               (=30)
    u16  h1                (0/1/256/257，标志位，含义未完全确认)
    u16  comps             (=7，每键分量数: 平移3 + 旋转4?)
    u32  0                 (保留)
    u16  version           (532 = 0x214；本格式；另一取值 6 为新格式)
    u16  K                 关键帧时间个数
K × f32 时间表（毫秒，30fps 对齐，首项 0；所有骨骼共享）
N 个骨骼数据块（顺序 = 骨名表顺序）
结尾可能有 1 个 0 填充字节
```

## 2. 骨骼数据块

以 `u32 块头` 开头：

### 2.1 静态块：块头 = 0x00000000

固定 34 字节（含块头）：

```
u32 hdr = 0
u16 1
3 × f32  平移 (x, y, z)            ← 12B
u16 1
6 字节   旋转（量化，见第 3 节）    ← 6B
u16 1
3 × f16  缩放 (sx, sy, sz)          ← 6B
```
该骨骼在所有 K 个时间点都用这一组值。

### 2.2 动画块：块头 = 0x00000100 / 0x00000101（实测值）

```
u32 hdr
u16 c1,  c1 个平移键 × 12B (3×f32)
u16 c2,  c2 个旋转键 × 6B  (量化旋转)
u16 c3,  c3 个缩放键 × 6B  (3×f16)
K 字节稀疏标志:
    byte[0]     = 0x07（通道掩码: bit0=平移, bit1=旋转, bit2=缩放）
    byte[1..K-1] 对应时间下标 1..K-1，逐键标志:
        bit0 = 该时间点有平移关键帧
        bit1 = 该时间点有旋转关键帧
        bit2 = 该时间点有缩放关键帧（实测该位几乎总是 0，缩放键数 c3 恒为 1）
```

**关键帧与时间的对应**（由反汇编与数据一致性验证）：

- 第 0 个时间点（time[0]）总是有键；
- 之后：`time[i]`（i=1..K-1）有键 ⇔ `byte[i]` 的对应 bit 置位；
- 因此 `c1 = 1 + popcount(byte[1..K-1] & 1)`，`c2 = 1 + popcount(... & 2)` 等。
  全量 2161 个文件校验：**0 个不匹配**。

插值：平移/缩放线性插值；旋转四元数球面插值（slerp）。`anim_decoder.py` 输出
已按 K 个时间点采样成逐帧数据，可直接逐帧使用。

## 3. 旋转量化编码（6 字节 → 单位四元数）**【核心】**

6 字节 = 3 个小端 `u16`：`u0, u1, u2`（即字节 [b0b1][b2b3][b4b5]）。

```
W32  = (u0 << 16) | u1          # 前 4 字节组成 32 位字
mode = W32 >> 30                # 高 2 位
A    = (W32 >> 15) & 0x7FFF     # 中间 15 位
B    = W32 & 0x7FFF             # 低 15 位
C    = u2 & 0x7FFF              # 第三个 u16 的低 15 位（最高位恒为 0/未用）

K1 = 4.3159689084859565e-05     # = sqrt(2)/32767 = 1/23169.767578125
K2 = -0.7071067690849304        # = -1/sqrt(2)

va = A*K1 + K2                  # ∈ [-1/√2, +1/√2]
vb = B*K1 + K2
vc = C*K1 + K2
# 第 4 个分量（被省略的最大分量，恒取正号）：
vw = sqrt(1 - va² - vb² - vc²)

full = [va, vb, vc, vw]
shift = (mode + 1) % 4          # 循环右移
q = full[-shift:] + full[:-shift]   # q = 单位四元数 (x, y, z, w)
# （最后再归一化一次，消除量化误差）
```

- `mode` 表示**被省略（即用 sqrt 重建）的分量下标**：0=x, 1=y, 2=z, 3=w。
- 编码器保证被省略分量取正值（四元数 q 与 -q 等价，可翻转符号），因此不需要符号位。
- 位域总长 2+15+15+15 = 47 bit，48 bit 中最高位（u2 的 bit15）未使用（全量 48 万+关键帧
  扫描确认恒为 0）。

反汇编对应（`libclient.so`，`0x9d4f58` 起）：对每个键读 `ldrh`×2 + `ldrh`，拼字，
按 `mode` 分四支；每支都是同一套 `x = f*K1 + K2`、`w = sqrt(1 - ...)`，然后
把三个分量按不同顺序写入四元数 4 个分量，重建分量写 `sqrt`。

## 4. 平移（t1）

`3 × float32`（小端），即骨骼局部平移（父骨骼坐标系）。

## 5. 缩放（t3）

`3 × IEEE754 binary16 (half)`，小端。通常 ≈ (1.0, 1.0, 1.0)。

## 6. 骨骼层级

`.anim` 文件本身**不含**父骨骼信息，需要从同角色 `.mesh`（或 `.gis` 容器）骨架获取。
LifeAfter 玩家骨架 51 骨（部分动画 52 骨，多一个辅助骨），骨名带空格（如 `biped l calf`），
对应 Blender/程序内名称通常把空格换成下划线。

## 7. 重要背景发现：`.gis` 容器（RGIS）与 `.ags` 文件

- `unpacked/players/_unknown/*.gis` 是 **RGIS 动画容器**，内含：
  ```
  [0x00] "RGIS"
  [0x04] u32 版本 = 0x03060001
  [0x08] u16
  [0x0a] u32 骨数 count
  [0x0e] count × 32B 骨名
  [..  ] count × 40B **绑定姿态**（float 精度）:
             平移 3×f32 | 四元数 (x,y,z,w) 4×f32 | 缩放 3×f32
  [..  ] 若干 animation blob，每个 blob 与本文第 1 节 `.anim` 格式相同
         （实测有 version=532 和 version=6 两种 blob）
  ```
- 该 float 绑定姿态是破解旋转编码的**关键对照数据**：解码后的 tpose 旋转与它逐骨一致。
- `*.ags` 是 "Skeletal extra file"（二进制 XML 配置，含 GisFiles / CutBones 等字段），
  不属于动画曲线数据。

## 8. 已知限制 / 未覆盖部分

- **version = 6 的 104 个 `.anim`**（文件名多为场景/剧情动画：`bosschuchang_sc*`、`ch1_sc*`、
  `RGIS_2` 等）块布局与 532 不同（数据头 h1=0、块内结构不同；从反汇编看新格式关键帧
  为「u16 键数 + 若干标志字节 + 平移 12B/键 + 旋转 4B/键 + 缩放 6B/键」，旋转是
  32 位打包：2bit 模式 + 3×10bit 分量，公式 `x = v*(32767/√2)⁻¹?  - 1/√2`，
  与 6 字节格式类似但分量范围 ±1/√2、10 位量化）。
  `anim_decoder.py` 目前对 version 6 直接报错；如需可参照 `libclient.so` `0x9d4514`
  的 4 字节旋转分支（`0x9d4b08`/`0x9d5408`）扩展。
- `.anim` 的 `h1`、`comps`、块头 0x101 与 0x100 的差异尚未完全解释（不影响解码）。
